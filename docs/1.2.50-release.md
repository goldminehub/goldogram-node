# goldogram-node 1.2.50

Fixes the sync stop at 1,845,956. Desktop nodes on 1.2.49 bundled a core that does not know the parent-replacement break at block 1,845,957 (added in protocol `79e8527`), so they refused the next block and stayed on "Syncing…". This build bundles the core from protocol main: that known break, the depth-1 reorg-race fix, DB-first persist, and halt on an unlinked block. After the update, a node resumes from its existing data and catches up to the tip. It does not wipe the data directory.

If a future block is refused and catch-up cannot heal it, the dashboard says "Sync stopped at block N — update required" instead of an endless "Syncing…".

The bundled core does not listen on `127.0.0.1:8099` unless `GOLDOGRAM_MINT_TEST_JWT=1`. The node and miner launch paths never set that variable.
